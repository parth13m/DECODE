# Strategic Decision

This decision is finalized.

Decode will provide AI access.

Users will NOT provide their own API keys.

Reasons:

1. Most target users do not have API credits.
2. Asking for API keys creates onboarding friction.
3. API setup reduces conversion.
4. Decode should feel like a product, not a developer utility.

As a result:

The existing provider-selection architecture is temporary.

Future architecture:

User
↓
Decode macOS App
↓
Decode Gateway
↓
Claude Sonnet
↓
Response

The API keys remain server-side only.

Users never see provider credentials.

# Alpha Objectives

The purpose of Alpha is NOT:

* Revenue
* Billing
* Monetization
* Enterprise infrastructure

The purpose of Alpha is:

1. Learn how users actually use Decode.
2. Identify the most valuable mode.
3. Measure engagement.
4. Collect qualitative feedback.
5. Validate product-market fit signals.
6. Identify abuse patterns.
7. Prepare for Beta.

---

# Guiding Principle

Build the smallest possible platform that allows:

1. User authentication
2. User management
3. Usage analytics
4. Admin controls
5. AI request routing

Do not build anything beyond this.

# Implementation Roadmap

## Milestone 1 — Analytics Foundation

Priority: P0

Goal:

Collect useful product intelligence immediately.

### Database

Create:

users

request_log

### request_log should track

* user_id
* timestamp
* mode
* latency
* status

Optional:

* input_tokens
* output_tokens

if available from provider responses.

### Admin Dashboard

Display:

* Total users
* Requests today
* Selection Mode count
* Screenshot Mode count
* Session Mode count
* Requests per user

No charts required.

Simple tables are sufficient.

### Success Criteria

Admin can determine:

* Which mode is used most
* Which users are active
* Which users are inactive

without asking users.

---

## Milestone 2 — Invite Code Authentication

Priority: P0

Goal:

Prevent unauthorized access.

### User Flow

First Launch

↓
Enter Invite Code

↓
Activate

↓
Receive Access Token

↓
Store in Keychain

### Database Fields

users

* id
* email
* invite_code
* token_hash
* status

status values:

* pending
* active
* disabled

### Admin Controls

Generate Invite Code

Enable User

Disable User

### Success Criteria

Only invited users can access Decode.

Disabled users lose access immediately.

---

## Milestone 3 — Decode Gateway

Priority: P0

Goal:

Move AI access from user-owned keys to Decode-owned keys.

### Gateway Responsibilities

Authenticate requests

Validate user status

Enforce quotas

Log analytics

Forward request to Claude Sonnet

Stream response back

### Requirements

SSE passthrough

Bearer token authentication

Request logging

Quota enforcement

### Success Criteria

macOS app never communicates directly with Claude.

All AI traffic flows through Decode Gateway.

# Alpha Success Definition

Alpha is successful if:

1. 10 invited users activate Decode.
2. Users consistently use Decode during development.
3. Analytics reveal clear usage patterns.
4. Most valuable mode becomes obvious.
5. Major UX friction points are identified.
6. Infrastructure remains stable.
7. Admin can manage all users.
8. Decode API costs remain controllable.

Only after these conditions are met should Beta planning begin.
